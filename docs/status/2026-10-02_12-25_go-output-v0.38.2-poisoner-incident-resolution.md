## d) TOTALLY FUCKED UP

1. **The fleet's own source of truth recorded the poisoner roles inverted for 10 days.** POISONERS.md (2026-09-22) claimed "v0.38.2+ is minor-form" while the published v0.38.2 `.mod` said `go 1.27.1`, and v0.38.1 — the supposedly-bad documented-only tag — was the clean one. The registry recorded release _intent_, not verified _published artifacts_, and every consumer sweep since trusted it. gvac's own AGENTS.md even said "tidy is stable — T1 fully landed" while its own directive sat at `1.27.1`.
2. **go-output shipped releases with broken gates.** Master lint was failing in 5 modules and CI red for ~2 days (toolchain pin + hidden lint debt); v0.38.1/v0.38.2 went out with no green pre-tag gate, no GitHub Release, and the release workflow silently dark since v0.38.0. The 2026-09-30 "fix" commit (`cac4497`) normalized only 16 of 19 modules — the incomplete fix itself became this session's starting evidence.
3. **The documented tag-then-bump convention was structurally a poison-preservation mechanism this cycle.** v0.38.2's tagged tree pins siblings at v0.38.2-era versions; had v0.38.3 followed the convention, every submodule graph would have kept dragging the `go 1.27.1` floor for another full release. Only luck (v0.38.1 being clean) made the convention look safe before.

## e) WHAT WE SHOULD IMPROVE

1. **Verify published artifacts, not intentions.** Every "release X is clean" claim in fleet docs should carry a verification command + date (e.g. `proxy.golang.org/<mod>/@v/<ver>.mod` content). This single rule would have prevented the 10-day inversion.
2. **Make `who-forces` the one-command answer.** It must name at-parity carriers (directive == max floor), not just "clean" — this session's core question was answerable by the tool and wasn't.
3. **Poisoner-fix releases: bump sibling pins before tagging, always.** One-time deviation this session; should be the documented standard (with the ADR-009/Pattern-B note updated).
4. **Run release gates and tag scripts in the identical environment** (`nix develop -c …`): the govulncheck gap aborted two gate runs because the script re-invoked the gate in a bare shell.
5. **Lint sweeps: all modules in one pass.** Per-module cascade (fix d2 → discover integration → discover markdown…) cost 4 gate reruns; one sweep collected all 6 in a single run.
6. **`--no-verify` must spawn a follow-up task, not just a justification.** Three bypasses this session share one root cause (go-licenses missing from go-output's devShell); none of them fixed it.
7. **Auto-commit-daemon "fix" commits deserve a diff review before being trusted as release content** (`cac4497`'s 16/19 incompleteness was only found because a consumer broke).
